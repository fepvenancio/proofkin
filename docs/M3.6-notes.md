# Milestone 3.6 notes: closing the QUORUM7 and MEDIAN5 holes

Not in PLAN.md's milestone table. Milestone 3.5 hardened GRID_PATH, KNAPSACK3, SORT8 and QUORUM7's boundary. A
review of it then found that QUORUM7 and MEDIAN5 still let wrong programs through, and a systematic search
(below) confirmed it. The contracts are immutable once deployed, so this was done before milestone 5.

## What changed

| Puzzle | Added | Trials a solution must pass |
|---|---|---|
| QUORUM7 | trials 10..16: voter k alone says yes, with t = 1 (k = 0..6). Trial 17: voters 1..6 say yes and voter 0 says no, with t = 7, one short | 18 (was 10) |
| MEDIAN5 | trials 10..12: `[40,120,80,160,200]`, `[160,40,200,120,80]`, `[120,160,40,80,200]`: shuffles of five distinct values with the median (120) at x1, x3 and x0 | 13 (was 10) |
| SORT8, GRID_PATH, KNAPSACK3, FAIR_SPLIT4 | nothing | 12, 16, 16, 10 |

Trials 0 to 9 and every random input are unchanged, so the renderer and its SVG snapshots are untouched again.

Why QUORUM7 and MEDIAN5 were open: QUORUM7's two fixed cases are unanimous (every vote the same), so a program that
reads one voter passes both. In MEDIAN5's two fixed cases the median is `x2` in both, so a program that gets the
network slightly wrong can still pass both. The random trials then decide, and for the worst bypass they did not.

Two fixes in the playground, from the same review:

- **"Test locally" runs the fixed cases first**, then the random ones. In trial order it ran the 8 random cases
  before the further fixed ones, so a wrong GRID_PATH program was named as a "random case" 82 times in 100 and as
  a named edge case only 18. It also ran too few fixed cases when asked for few random ones: `randomTrials: 0`
  passed a program that the contract would refuse. Now every fixed case runs, whatever `randomTrials` is.
- **The mint panel follows the commit in flight.** Continuing a saved commit of another puzzle showed the open
  tab's puzzle ("GRID_PATH slots left") above the other puzzle's salt and "Send commit". The panel now describes
  the commit's puzzle, and "Continue" takes the page to that puzzle.

|---|---|---|---|
| QUORUM7 | 542,791 | 712,151 | +169,360 (about 21k a case) |
| MEDIAN5 | 490,672 | 562,926 | +72,254 (about 24k a case) |
| SORT8 | 1,177,900 | 1,178,120 | +220 |
| GRID_PATH | 1,015,541 | 1,015,923 | +382 |
| KNAPSACK3 | 1,209,013 | 1,209,395 | +382 |
| FAIR_SPLIT4 | 584,948 | 584,988 | +40 |

The small changes are the extra comparisons in `trialCount`. The worst case is still KNAPSACK3 at 1.21M gas.

Exact pass rates (QUORUM7 has 896 possible inputs: 128 vote patterns by 7 thresholds, so these are not sampled).
A program "gets through" if it passes both fixed cases and all 8 random trials, and the best of 5 salts is a
committer who tries 5 commits:

| Wrong QUORUM7 program | Before | Now |
|---|---|---|
| reads only voter 0 (the playground's own starter) | 1.14%, 5.6% best of 5 | 0% |
| majority of voters 0 to 2 | 1.85% | 0% |
| majority of all seven, ignoring t | 3.44% | 0% |
| `sum >= min(t, 4)` / `min(t, 5)` / `max(t, 2)` | 22% / 64% / 94% | 0% |

For MEDIAN5, bypassing one node of the 15-node solution (there are 20 such programs): 14 got through, on 6 to 17% of
seeds per commit (the worst, `hi` replaced by `b`, 14 nodes, 17%). **After: all 20 are caught by a fixed trial on
every seed**, and so are all 16 bypasses of the QUORUM7 solution, all 28 of GRID_PATH's and all 63 of KNAPSACK3's.
(The search is a scratch script, not part of the repository; it bypasses each node of each fixture solution in
turn, drops what becomes dead, and runs the result on the fixed trials and on 8 random ones over 1,500 seeds.)

## How it was checked

Written test-first; each test below failed before the change.

- The wrong programs of milestone 3.5 grew from 42 to 74: 12 QUORUM7 shortcuts (each voter alone, two majorities,
  three bent thresholds) and the 20 MEDIAN5 bypasses, built in `packages/vm/src/cheats.ts`. Against the old fixed
  cases **26 of the 32 new ones got through**. Now all 74 fail a fixed trial on every seed, in TypeScript and
  Solidity, through the real `commit`/`reveal`, with a fuzz test over random salts.
- Property tests for the new cases in both languages: each QUORUM7 case has exactly its voter saying yes, the
  last is one short, and the three MEDIAN5 cases are shuffles with the median where it is claimed.
- Playground: the order of the local test, `randomTrials` below the number of fixed cases, the case descriptions
  on the page, and the ordinals up to "tenth".
- **The resume desync was reproduced in a real browser before the fix and checked after it**, against a local
  chain with a wallet shim and a saved SORT8 commit. `src/ui/` still has no automated tests, so this one has no
  test that would fail if it came back.
- **Tests:** Solidity 208 (2 more than before this milestone), `packages/vm` 517 (131 more, almost all of them the
  new wrong programs, which get four checks each), playground 160 (5 more). Slither: 0 High, 0 Medium, 0 Low, the
  same three informational detectors. Coverage of `src/`: 100% of lines, 99.8% of statements, 98.8% of branches.
- **Rehearsal on a throwaway chain, repeated on these contracts** (`docs/M5-notes.md`): the deploy script, then
  `pnpm launch:dry-run` mints all six fixture solutions and reads each back; deployment 7,000,906 gas; code sizes
  Proofkin 14,003 bytes and Renderer 17,521, against the 24,576 limit.
- **Mutation testing:** 8 new mutants in the `vm` suite and `playground` suites (QUORUM7's or MEDIAN5's further
  cases never run, the wrong voter asked, the near miss not one short, a changed shuffle; the local test going back
  to trial order, running the fixed cases backwards, dropping them from the count), and one pattern rewritten.
  All five suites were then run in full: **110 mutants, none survived** (`vm` 22, `proofkin` 35, `deploy` 14,
  `renderer` 7, `playground` 32), and a hash comparison afterwards showed every source file back byte for byte. The
  playground stage counts a timeout as a kill, so the four mutants of the local test were also applied by hand:
  each fails the assertion meant for it, with no timeout.

## What this does not fix

- **Grinding is still possible** for any wrong program that gets through every fixed case and is lucky on the 8
  random ones. The search covers one-node bypasses of the fixture solutions and the shortcuts above; a wrong
  program built some other way is only as unlikely as the random trials make it.
- **Residual bypasses**: six FAIR_SPLIT4 variants (20 nodes) and two SORT8 variants (45 nodes) still get through,
  on well under 1% of seeds: 0.07% to 0.4% across two runs of 1,500 seeds, which is too few hits to pin down. A
  committer who tried 20 salts would still be below 10% for any of them. Closing them would cost more fixed cases.
- Variants of one solution still mint as separate tokens.
- Nothing is deployed.
